# Ground Truth Generation Plan

## What we're building

Independent reference files for each test PDF, generated by reading the PDFs
directly (not by running the parser). These become authoritative ground truth:
the parser is tested against what the output *should* be, not against what it
currently produces.

## Why this is better than snapshot testing

Snapshot testing captures parser output and calls it correct. If the parser
has a bug, the snapshot inherits that bug and the test passes. This approach
inverts that: Claude reads each PDF and produces the reference independently.
Discrepancies between the reference and parser output are always real bugs.

## Step 1 — Generate reference files (Claude reads each PDF)

For each PDF in `Test PDFs/`, Claude reads the file, identifies every scene
and every element, and writes a reference JSON to
`Test PDFs/reference/<ScriptName>.json`.

**Output format** — mirrors what `parse_pdf()` returns:

```json
{
  "title": "The Harvest",
  "characters": ["ADA", "JOSH", "MARCUS", ...],
  "scenes": [
    {
      "number": 1,
      "title": "THREEDAYSTODEPARTURE",
      "elements": [
        { "kind": "stage_direction", "speaker": null, "text": "AFTERNOON. JOSH, DENISE..." },
        { "kind": "dialog",          "speaker": "ADA",  "text": "In Jesus name we pray." },
        { "kind": "parenthetical",   "speaker": "ADA",  "text": "(pause)" },
        ...
      ]
    }
  ]
}
```

**Element kinds**: `dialog`, `stage_direction`, `parenthetical`, `scene_heading`

For `overlap_cue` elements (simultaneous speech like "A / B"), use kind
`dialog` and set `"overlap_cue": true`.

**Text normalization**: match what the parser produces — no leading/trailing
whitespace, Unicode preserved as-is (curly quotes, em-dashes, etc.).

## Step 2 — Write the comparison test

`backend/tests/test_reference.py` — for each PDF that has a reference file:

1. Run `parse_pdf()` on the PDF
2. Compare every scene title, element kind, speaker, and text against the
   reference JSON
3. Report diffs clearly: `scene N, element M: expected kind=X speaker=Y,
   got kind=X' speaker=Y'`

The test should be **lenient on text** (substring match or normalized
whitespace) but **strict on kind and speaker** — those are the attribution
properties we care most about catching regressions in.

## Step 3 — Decide tolerance policy

Some differences are acceptable (the parser may merge/split adjacent stage
directions, vary punctuation). Agree on what counts as a pass:

- `kind` mismatch → always a failure
- `speaker` mismatch → always a failure  
- `text` mismatch → warning, not failure (unless speaker or kind also wrong)
- Extra/missing elements → failure if element count differs by > N%
- Scene count mismatch → failure

- Stereophonic: partial reference is fine — cover what works, mark the
  two-column sections as known-incomplete
